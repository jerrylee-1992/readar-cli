# Readar CLI architecture

The independent TypeScript / Node.js CLI communicates only through HTTP. `src/main.ts` owns argument validation and JSON output; `src/client.ts` owns authenticated requests and refresh rotation; `src/store.ts` owns restricted local session files and process locks.

`src/records.ts` delegates listings and details to the server’s global `/v1/questions` and `/v1/notes` routes, passing filters and wrapping the signed server cursor with an API/account/filter fingerprint. Version 1 scan cursors are rejected. Each listing page or detail uses one normal authenticated request; no episode traversal occurs. Authentication refresh, if necessary, adds its existing request.

The backend indexes changed questions and notes in Tablestore asynchronously. PostgreSQL remains the payload and authorization source. Search uses relevance order; listings without a query use descending creation/ID/episode order. The output carries `search_mode` and `consistency`. Search failures are propagated with stable errors rather than falling back to local scanning.

`src/search.ts` implements unified content search through authenticated `GET /v1/search`. Required `--query` accepts a semantic description of 1–500 Unicode characters after trimming. `--type all|articles|episodes|questions|thoughts` selects saved content (default `all`, covering all four types), `--exclude-archived` changes the default inclusion of archived articles, and `--mode hybrid|keyword` defaults to `hybrid`. Questions cover question text, full answers and summaries; thoughts include only note kind `thought`. Title and body are always searched together; no field selector is exposed. `--limit` is 1–50, default 20. Requests always send `include_records=true`, including continuations, to declare support for question/thought results; the backend keeps legacy `all` requests restricted to articles and podcasts. Existing question/note commands retain keyword, date, episode and kind filters and their current behavior.

Each content-search page is one normal authenticated request, plus refresh if required. The CLI wraps the server's opaque search-session cursor in a distinct envelope bound to the API, account, trimmed query, type, archive selection and mode. A changed page limit is allowed. It rejects question/note cursors and mismatched bindings before sending a search request. The existing client pins the account between reading the binding and the authenticated request, aborting on an account change. The backend still authenticates every request and validates its own signed cursor; the local fingerprint is not an authorization boundary.

The output preserves source excerpts, IDs/types, `source_version` and article/transcript anchors without generating summaries or estimated timestamps. Question/thought hits add raw `record_id`, `episode_id` and `episode_title`; their composite `id` stays opaque. Exact details use the raw UUID with `questions get`/`notes get --episode`. Child anchors use a text chunk `paragraph_index`, a canonical episode `position_seconds` or null, and null `segment_number`/`track_version`; they are not natural/generated transcript track seek positions. The CLI rejects malformed child IDs, parent context, source versions, snippets and anchors while preserving the existing article/episode response contract. A title-only result may have a null anchor. It also validates the selected `search_mode`, `consistency: eventual`, `indexing_status: ready|partial`, candidate-cap status and pagination metadata. A keyword response to a hybrid request is an invalid response. An empty page with a continuation remains a valid page; candidates may have changed or failed source revalidation. `candidate_limit_reached` reports a bounded candidate cap, never a complete match count.

Hybrid retrieval depends on separately configured backend keyword and embedding services. It has no automatic keyword or scan fallback. HTTP 503 `search_unavailable` produces exit 1; HTTP 410 `search_expired` produces exit 2 with instructions to start a new search; HTTP 422 cursor/input errors retain exit 2. Error response text is not echoed. Asynchronous indexing and history backfill can leave coverage partial and newly changed content temporarily absent. Server errors are distinct from successful empty results.

Collection and authentication continue to use existing Readar endpoints. This repository contains no cloud SDK, backend imports or database access. Distribution documentation distinguishes Git/source installation from future registry installation. Local build, subprocess contract tests and `npm pack` do not establish backend deployment, semantic quality or production index readiness. The repository skill source is packaged alongside the CLI; updating it does not update an installed user skill automatically.
